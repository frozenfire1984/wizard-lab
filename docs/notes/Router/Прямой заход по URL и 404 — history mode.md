# Прямой заход по URL и 404 — history mode

> Записано 24.09.2026 со слов Claude, **принято на веру**. Эксперимент не проводил —
> задача висит в [TODO](../../TODO.md), раздел «Хвосты и мелочи».

**Контекст:** разбирали `RouterView` / `RouterLink`, всплыло, что в бою прямой заход на
`/about` может дать 404, а в `wizard-lab` при F5 на `/about` всё работает.

## Главное: URL обрабатывается в двух разных ситуациях

| Ситуация | Кто обрабатывает | Идёт ли запрос на сервер |
|---|---|---|
| Клик по `<RouterLink>` внутри загруженного приложения | роутер в браузере | **нет** |
| Ввод адреса, F5, переход по ссылке из мессенджера | сервер | **да**, честный `GET /about` |

Путаница обычно тут: кажется, что маршрут `/about` «существует». Он существует только в
таблице маршрутов внутри JS.

## Что физически лежит на сервере после сборки

```
index.html
assets/index-a1b2c3.js     ← всё приложение, все компоненты, роутер
assets/index-d4e5f6.css
```

Ни файла `about`, ни папки. Обычный nginx на `GET /about` ищет файл по пути, не находит → **404**.

Замкнутый круг: чтобы показать `/about`, нужен загруженный JS; чтобы загрузился JS, нужен
`index.html`; а сервер вместо него отдаёт 404.

## Решение — fallback на index.html

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

«Попробуй файл → попробуй папку → иначе отдай `/index.html`».

Дальше: браузер получил `index.html` → загрузил JS → приложение стартовало → роутер прочитал
адресную строку → показал `AboutView`. Пользователь ничего не заметил.

## Это то же, что в Laravel

На диске нет ни `/items`, ни `/items/7/edit` — есть только `public/index.php`, и правило сервера
«все запросы в одну точку входа». Разница одна: **где живёт таблица маршрутов** — в PHP на
сервере или в JS в браузере. Правило для веб-сервера одинаковое.

## Два режима роутера

Выбираются в `src/router/index.ts`:

| Режим | URL | Что уходит на сервер | Нужна настройка сервера |
|---|---|---|---|
| `createWebHistory()` | `site.com/about` | `GET /about` | **да** |
| `createWebHashHistory()` | `site.com/#/about` | `GET /` | нет |

Всё после `#` браузер на сервер **не отправляет вообще** (исторически это якорь — адрес места
внутри страницы). Поэтому хеш-режим работает на любом тупом хостинге без конфига. Цена —
уродливый URL и исторически плохая индексация поисковиками.

**History mode** — это первый вариант. Название от History API: браузерный механизм, который
меняет адресную строку и историю переходов без запроса к серверу. В скаффолде стоит он.

## Почему в wizard-lab F5 работает

`npm run dev` — это **dev-сервер Vite**, у него SPA-fallback встроен. То же правило, только не
руками в конфиге. Проверяется в DevTools → Network → F5 на `/about`: первый запрос типа
`document`, статус **200**, во вкладке Response — `index.html` с пустым `<div id="app">`,
а не разметка страницы About.

## Как увидеть 404 живьём

```bash
npm run build                        # собрать в dist/
python3 -m http.server -d dist 8000  # тупой файловый сервер, БЕЗ fallback
```

Главная работает → клик «About» работает (роутер в браузере) → **F5 = 404**.

Для контраста: `npm run preview` — та же собранная `dist/`, но с fallback, F5 работает.
Разница исключительно в поведении сервера.

## Вывод

Ошибка «поставил `<a href>` вместо `<RouterLink>`» на глаз не ловится: страница перезагрузится,
приложение поднимется заново, роутер покажет тот же экран. Ловится по последствию — **пропало
состояние**: пользователь был на третьем шаге визарда, кликнул, оказался на первом с пустой
формой.
