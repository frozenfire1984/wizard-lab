# COURSE.md — визард-лаб: курс и живые записи

## Зачем это

Юрий пишет руками визард — многошаговую форму — чтобы вернуть понимание Vue.

⛔ **Мы не копируем рабочий визард Advertise.** Сначала план был именно такой, от него отказались
23.09.2026: за один рабочий день у того визарда поменялись порядок шагов, развилка после поиска,
порядок тарифов и половина вёрстки. Завтра поменяется ещё раз. Гнаться за ним — значит учиться
переносу чужих решений, то есть ровно тому, от чего уходим.

Поэтому каждое решение здесь принимается **по общепринятой практике**, а не по тому, как сделано
в бою. Сюжет остаётся знакомым — поиск объекта по адресу, выбор из найденного, выбор тарифа, —
потому что домен привычен и не надо тратить внимание на придумывание. Но если практика расходится
с тем, что делает Advertise, выигрывает практика.

Realmo остаётся в курсе в одной роли: как источник живых болячек. Что из здешних решений стоит
принести в рабочий визард — копится в разделе «📋 Что нести на работу» в конце файла.

## Целевая структура

```
src/
  types/        доменные типы: Listing, Plan, Address, SearchResult
  api/          типизированный интерфейс ручек + фейковая реализация (позже — HTTP в Laravel)
  stores/       wizard.ts (состояние флоу), auth.ts (пользователь)
  router/       маршруты шагов и гарды
  views/        экраны-шаги: Address, Select, Result, Plans
  components/   презентационные кусочки: карточка листинга, карточка тарифа, поле адреса
```

Одно правило, которое держит всю конструкцию: **компоненты не ходят в API напрямую — только через
стор.** Компонент показывает и сообщает о действии пользователя; решение «что при этом происходит»
принимает стор. Именно отсутствие этого правила размазало рабочий визард по сорока инжектам.

Второе правило: **шаг не хранит состояние.** Всё, что переживает переход между шагами, живёт
в сторе; компонент шага можно выкинуть и написать заново, ничего не потеряв.

## Что сознательно упрощаем

Учим **устройство** визарда, а не объём приложения. Сознательно НЕ делаем:

| Чего не будет | Почему |
|---|---|
| Капча (Turnstile) | ничему не учит, только мешает тестам |
| Настоящий OAuth и сессии | вместо этого эмуляция входа, веха 5.5 |
| Оплата, Stripe | после выбора тарифа — заглушка «здесь была бы оплата» |
| Загрузка фотографий | отдельная большая тема, не про устройство флоу |
| SSR, SEO, мультидоменность | специфика боевого проекта |
| Vuetify, дизайн-система | стили здесь второстепенны |
| Пиксель-перфект и мобильная вёрстка | адаптив «чтобы не разваливалось», не более |

Что при этом **обязательно остаётся**, потому что в нём вся суть: шаги и гарды, единый источник
правды, типизированный контракт, состояния загрузки и ошибок, восстановление после перезагрузки,
e2e-тесты.

Импорт объявления по ссылке (в бою — ветка с парсингом и опросом статуса) оставляем как
**необязательную позднюю веху**: это хорошая практика по асинхронности, но без неё курс полон.

## Вехи

### −1. Словарь (час, не больше)

Не изучение, а снятие спотыкания о слова. Двенадцать понятий, каждое одной строкой и с примером —
удобно брать пример из рабочего кода, который Юрий уже видел живьём:

`ref` · `computed` · `watch` · пропсы и события · слоты · `provide/inject` · композабл · стор ·
маршрут и его параметры · вложенные маршруты (`children`) · гард (`beforeEnter`) · `onMounted`.

**Готово, когда:** Юрий может своими словами сказать, чем `computed` отличается от `watch`
и зачем вообще нужен гард. Не заучивать — узнавать в тексте.

### 0. Разминка — todo-лист

Скаффолд `npm create vue@latest` (TS, Router, Pinia, Vitest, Playwright, ESLint, Prettier) и
маленький todo своими руками. Он нужен не сам по себе: это скелет будущего визарда в миниатюре.

Должен задействовать: типизированную модель задачи, `v-for` по списку, computed-фильтр
(все / активные / выполненные), Pinia-стор вместо локального `ref`, один роут, сохранение в
`localStorage` и восстановление при перезагрузке.

**Готово, когда:** перезагрузка страницы не теряет задачи, а фильтр живёт в URL.

### 0.5. Первый e2e своими руками

Playwright, один сценарий на todo: добавил задачу → переключил фильтр → перезагрузил → задача на
месте. Три действия, но в них вся суть e2e: проверяем поведение, а не разметку.

**Готово, когда:** тест зелёный, и Юрий может объяснить, чем `getByRole` лучше селектора по классу.

### 1. Шаги визарда через роутер

Шаг живёт в query (`?step=address|select|result|plans`), навигация только через роутер, прямой
заход на поздний шаг со свежей сессией возвращает на первый.

**Готово, когда:** кнопка «назад» браузера ведёт себя предсказуемо, а дип-линк не показывает пустой экран.

### 2. Стор

Всё состояние визарда — в одном Pinia-сторе: выбранный тип сделки, адрес, найденные объекты,
выбранный объект, выбранный тариф, флаги загрузки и ошибок. Компоненты читают из стора, а не
прокидывают друг другу пропсы через три уровня.

**Готово, когда:** ни одного `provide/inject` для состояния, и по стору видно всё состояние флоу целиком.

### 3. Формы и валидация

Поле адреса с подсказками, выбор типа сделки, выбор тарифа. Валидация до отправки, понятные ошибки.

### 4. Асинхронность и ошибки

Загрузки, отмена предыдущего запроса, обработка провала, пустые состояния. Все сценарии фейкового
API должны быть проходимы руками.

### 5. Восстановление состояния

Перезагрузка посреди флоу не теряет прогресс; протухшее состояние не показывает экран, которого
пользователь не видел.

### 5.5. Авторизация — эмуляция

Не настоящая: экран входа, который просто кладёт пользователя в стор и в `localStorage`.
Но с одной честной деталью — **вход перезагружает страницу целиком**, как настоящий
OAuth-редирект. Без этого исчезает вся суть упражнения.

Что должно получиться:

- часть флоу доступна гостю, часть требует входа (гард на маршруте, `meta.requiresAuth`);
- после входа пользователь возвращается туда, откуда его увели, а не на первый шаг;
- действие, прерванное входом («выбрать тариф», «сохранить черновик»), **доигрывается само**
  после возврата — состояние пережило перезагрузку.

Почему это стоит проходить руками: в рабочем визарде realmo самые злые баги живут именно здесь —
граница «до логина / после логина», флаги `adv_prepared_*` для возобновления действия и
восстановление состояния после редиректа.

### 6. Настоящий бэкенд

Laravel под тем же контрактом, затем Postgres вместо массивов в памяти. Фронт и e2e-тесты не
меняются ни строчкой — это и есть главный урок про контракт.

## Контракт фейкового API (этап 1)

Модуль `src/api/` с типизированным интерфейсом и фейковой реализацией. Контракт придуман здесь,
по практике, а не срисован с боевых ручек:

| Метод | Что делает | Что возвращает |
|---|---|---|
| `search(query, type)` | поиск объекта по адресу | `items[]` (может быть пусто) + распознанный `address` (может быть `null`) |
| `selectListing(id)` | выбор объекта из нескольких | карточка объекта |
| `getPlans()` | тарифы | три тарифа с ценой и названием |
| `savePlan(plan)` | запомнить выбор тарифа | ok |
| `parseUrl(url)` | импорт объявления по ссылке | распознанный объект либо ошибка |

Сценарии, которые фейк обязан уметь (каждый вызывается руками и покрывается тестом):

- нашли ровно один объект;
- нашли несколько — нужен экран выбора;
- не нашли, но адрес распознан — ведём на тарифы;
- не нашли и адрес не распознан (ввели мусор) — ошибка на месте;
- импорт по ссылке упал;
- медленный ответ — проверяем индикаторы загрузки;
- сервер ответил ошибкой.

Данные генерирует Claude: правдоподобные адреса США, типы объектов (офис, склад, ритейл, земля),
площади, цены за sq ft, статусы for sale / for lease.

## 📋 Что нести на работу

Живой список: что из увиденного в песочнице стоит принести в рабочий визард realmo. Ведём по ходу,
не откладывая. Формат записи: **симптом → причина → что предложить**. Когда пункт доехал до
рабочего кода — помечать ✅ и номером тикета.

Затравка из того, что уже болит на работе (сентябрь 2026, ветка RLM-1604):

- **Роутер используется как держатель URL, а не как навигация.** `/advertise` — один плоский роут
  без `children` и без `beforeEnter`; шаги переключаются вычисляемым свойством внутри компонента;
  защита дип-линка написана как `watch` на query с `router.replace` внутри, то есть гард
  переизобретён снаружи механизма гардов; «назад» ходит по индексу массива, а не по истории,
  поэтому кнопка браузера и кнопка интерфейса — две разные навигации. Вложенные роуты в том же
  файле роутера у других разделов используются, значит возможность была.
  Предложить: либо шаги как вложенные роуты со своими `beforeEnter`, либо явная машина состояний
  в сторе — главное, одно место, решающее «можно ли быть на этом шаге и куда ведёт назад».
  Сейчас таких мест три: watcher, computed и `localStorage`. Из этого пункта растут почти все
  остальные в этом списке.
- **Прогресс-бар схлопывается в импорт-ветке.** Причина: список шагов линейный, а флоу — нет;
  порядок приходится переставлять вручную в computed. Предложить: шаги как данные конкретного
  маршрута, а не один глобальный массив.
- **Флаг «ничего не найдено» воскресает из localStorage.** Причина: состояние живёт в браузере,
  а не в сторе, и восстанавливается без учёта того, на каком шаге пользователь.
- **Кнопка «назад» вынуждена ветвиться.** Причина: шаг знает только свой индекс, а не то, откуда
  в него пришли. Предложить: хранить в сторе путь, а не позицию.
- **Гард дип-линка гоняет на первый шаг по флагу в localStorage.** Причина: нет единого понятия
  «флоу начат».
- **`EventService.js` не типизирован.** Из-за этого поля ответов (`data.data.address`, `item`)
  выясняются чтением чужого кода. Предложить: типы на ответы ручек визарда.
- **Состояние размазано по ~40 `provide/inject`.** Корень всего перечисленного выше.
- **Pinia на проекте стоит и подключена во всех точках входа, но ни один компонент её не
  использует** — запрет был устный, технической причины нет.
