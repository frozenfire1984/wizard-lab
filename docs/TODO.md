  ```yaml

      runs-on: self-hosted
      steps:
        - uses: actions/checkout@v4

  ```

  ```ts
  export type Timestamp = number | null
  ```

  `null` зашит **внутрь имени** — и везде, где стоит `Timestamp`, автоматически разрешается
  «ничего», даже там, где значение точно есть. В `SubmitOrderResponse.date` сервер дату
  возвращает всегда, но компилятор требует проверки на `null`, которой быть не должно.

  Как честнее:

  ```ts
  type Timestamp = number        // просто число

  date: Timestamp                // там, где дата точно есть
  date: Timestamp | null         // там, где её может не быть — видно в месте использования
  ```

  **Правило:** имя типа говорит, **что это**. Может ли значение отсутствовать — свойство
  конкретного места, а не самого типа.

  Тот же случай, что `string | ''` и `DeliveryMethod | 'pickup'`: не прятать особенности внутрь
  имени, пусть будут видны там, где используются.
  См. `KNOWLEDGE/cheatsheets/типы-и-интерфейсы.md`.
